01 / Hlavní příběh · vývojáři s Claude Code

Claude Code: volba „Yes, and don't ask again“ může uložit příkaz i s heslem do souboru, který se pak může dostat na GitHub. Apiiro našlo tajemství v 1 122 veřejných kopiích toho souboru.

Výzkum Apiiro, 5. 11. · data sebraná 1.–3. 11.

Apiiro: výzkum ↗The Hacker News ↗

„Skutečné tajemství“ znamená podle Apiira údaj ve formátu známého poskytovatele nebo heslo u veřejného serveru, ne ověřeně platný klíč; žádný údaj Apiiro nepoužilo ani netestovalo. Jedna upozorněná firma podle Apiira potvrdila, že její klíč byl aktivní. Vlastní pozorování nemáme.

Claude Code · .claude/settings.local.json · Apiiro: 104 185 / 104,185 · 1 122 / 1,122 · 1 379 / 1,379

Týká se vás, pokud používáte Claude Code a u příkazu s heslem, tokenem, klíčem nebo připojovacím řetězcem jste zvolili „Yes, and don't ask again“. Globální gitignore, který Claude Code nastaví, podle Apiira nepokrývá složku, ze které se repozitář stane až později, klon na jiném stroji ani soubor, který už někdo commitnul. Podmínky ↗

Dopad: podle Apiira se schválený příkaz uloží doslova jako pravidlo do .claude/settings.local.json; soubor nic v repozitáři neoznačuje jako soukromý, takže se commitne s ostatním kódem. Většina takových souborů se na GitHub nikdy nedostane. Ze 104 185 veřejných kopií jich 1 122 obsahuje tajemství, dohromady 1 379 různých tajemství, z toho 379 hesel k databázím. Apiiro to reprodukovalo s modely Opus 5.5 i Fable 5.1 a uvádí, že jde o chování Claude Code, ne modelu. Podklad ↗

Další krok

Podle Apiira: nejdřív vyměňte každé heslo, token a klíč, který soubor kdy obsahoval, protože smazání nevyčistí historii, forky ani klony. Pak soubor odeberte z gitu (git rm --cached .claude/settings.local.json) a přidejte do .gitignore projektu. I když v commitu nikdy nebyl, smažte z něj každé pravidlo s tajemstvím. Schvalujte vzory, např. Bash(npm run:*), místo doslovných příkazů, a tajemství odkazujte jako proměnnou ze správce tajemství ($DB_URL).
